# Разработка и проверка

## Окружение

Платформа: Windows x64, Python 3.13. Установка из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 setup
```

Скрипт использует `uv`, если он установлен; иначе стандартный `venv` и `pip`. Зависимости берутся из [requirements-dev.lock.txt](../requirements-dev.lock.txt), без примеси глобальных пакетов. Окружение создаётся в `%LOCALAPPDATA%\OlegPainter\dev-venv` — вне папки проекта, чтобы её не раздували синхронизация и поиск. Для нескольких рабочих копий задайте `OLEGPAINTER_VENV` абсолютным путём перед `setup` и остальными командами.

[requirements.txt](../requirements.txt) описывает зависимости приложения, [requirements-dev.txt](../requirements-dev.txt) добавляет инструменты разработки. Lock-файл фиксирует проверенный набор для Windows/Python 3.13; при обновлении синхронно проверяйте диапазоны, lock, `doctor` и тесты. Numba 0.65 не импортируется с NumPy 2.5 — рабочая связка зафиксирована с NumPy 2.4.

## Команды

| Команда `dev.ps1` | Назначение |
| --- | --- |
| `setup` | создать окружение и поставить зависимости |
| `doctor` | проверить окружение, импорты и ресурсы |
| `context [символ]` | карта исходников; с именем — найти определение с номером строки |
| `check` | окружение, критические ошибки Python (ruff), локальные ссылки документации |
| `test [аргументы pytest]` | автоматические проверки без видимых окон |
| `preview-overlays` | рендер экранных инструментов и проверка лишних перерисовок |
| `run` / `quick` | запустить основное окно |
| `fresh [nodriver]` | запустить программу как в первый раз — с пустыми настройками во временной папке; `nodriver` показывает её как на компьютере без драйвера |
| `build` | собрать EXE через PyInstaller |
| `package` | упаковать собранную программу в архив для релиза `dist/OlegPainter-<версия>-win64.zip` |
| `publish ["описание"]` | обновить публичный репозиторий: без описания — показать изменения, с описанием — закоммитить и отправить |

Пример: `powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 test tests/test_stable_dev_runtime.py`. Внутри открытого PowerShell можно писать `& .\dev.ps1 check`, если политика разрешает скрипты; ключ `-ExecutionPolicy Bypass` действует только на новый процесс.

## Тесты

`test` отключает автозагрузку посторонних pytest-плагинов, включает pytest-timeout и ставит `QT_QPA_PLATFORM=offscreen`. [tests/conftest.py](../tests/conftest.py) направляет `OLEGPAINTER_CONFIG_DIR` и Qt settings во временную папку: тесты не трогают реальные настройки, калибровки и картинки. Мышь в тестах заменена записывающим транспортом, холст — симулятором [tests/helpers/sim_pen.py](../tests/helpers/sim_pen.py).

Для одного теста передайте `tests/файл.py::ИмяКласса::имя_теста`. Реальное рисование автоматические тесты не запускают: для него нужны драйвер, цель и выделенная область.

## Как у нового пользователя

`dev.ps1 fresh` открывает программу так, как её видит человек, запустивший её впервые: «Быстрый старт», настройки по умолчанию, без профилей и калибровок. Всё, что программа запишет, попадает во временную папку `%TEMP%\OlegPainter-fresh` (она очищается при каждом таком запуске): `OLEGPAINTER_CONFIG_DIR` переносит туда и папку `configs`, и собственные настройки окна, которые обычно лежат в реестре. Ваши настройки, калибровки и картинки не меняются. Работает только одна копия программы — перед запуском закройте обычное окно.

`dev.ps1 fresh nodriver` дополнительно показывает программу как на компьютере без драйвера Interception (`OLEGPAINTER_DRIVER_PREVIEW=missing`): красная полоса, окно с предупреждениями и галочками. В этом режиме кнопки установки и перезагрузки ничего не меняют. Другие состояния для проверки: `reboot`, `blocked`, `unreachable`, `incomplete`, `broken`, `no_mouse`, `pending_removal`.

## Экранные интерфейсы

`dev.ps1 preview-overlays` запускает [preview_overlays.py](../tools/preview_overlays.py): рендерит настоящие Qt-виджеты на тестовых данных в `test-results/overlays/` и сохраняет PNG и `idle-report.json`. Слушатели мыши, хоткеи, движок и сессия пользователя при этом не запускаются. [preview_quick.py](../tools/preview_quick.py) так же рендерит страницы QML на изолированных данных.

## Сборка

`dev.ps1 build` собирает [OlegPainter.spec](../OlegPainter.spec) в `dist/OlegPainter`: QML-файлы, модули Qt Quick и ресурсы. Модели ИИ и драйвер в сборку не входят; неиспользуемые модули Qt (браузерный движок, 3D, PDF) и видеокодек OpenCV вырезаются. Запуск из исходников не доказывает, что пакет работает. Проверяйте копию сборки:

```powershell
.\dist\OlegPainter\OlegPainter.exe --self-test report.json
```

Самопроверка без видимого окна загружает интерфейс, готовит тестовую картинку, компилирует маршруты и проверяет нативные модули; настройки пользователя не трогает. Код возврата 0 — всё в порядке, подробности — в `report.json`. Захват экрана и рисование всё равно проверяйте вживую. Запускайте копию из короткого пути: при пути длиннее ~260 символов Windows не загружает плагины Qt.

## Выпуск версии

Программа находит обновление сама (UPDATE-001): раз в день спрашивает GitHub о последнем релизе и сравнивает его тег с `APP_VERSION`. Чтобы пользователи получили новую версию:

1. Поднимите `APP_VERSION` в [application/support.py](../application/support.py), обновите `WHATS_NEW` и [CHANGELOG.md](../CHANGELOG.md).
2. `dev.ps1 build`, затем самопроверка копии из короткого пути.
3. `dev.ps1 package` — архив `dist/OlegPainter-<версия>-win64.zip`: одна папка `OlegPainter` с программой и лицензиями, без `configs`, `logs` и `models`.
4. Создайте релиз с тегом `v<версия>` (не черновик и не pre-release), приложите архив и опишите изменения — этот текст программа покажет как «Что нового».

Программа берёт архив по имени `OlegPainter-…-win64.zip` и проверяет SHA-256, который GitHub публикует для каждого файла релиза. Пока репозиторий закрыт, проверка отвечает «Опубликованных версий пока нет». Для проверки без сети задайте `OLEGPAINTER_UPDATE_URL` — адрес файла с ответом в формате GitHub API (подходит и `file:///…`).

## Публичная выгрузка

Перед публикацией собирайте чистую копию проекта: `python tools/export_public.py <папка>`. Скрипт копирует только файлы, разрешённые `.gitignore`, и проверяет, что среди них нет личных данных: настроек, журналов, моделей, таблиц.

`dev.ps1 publish` обновляет уже созданный репозиторий выгрузки (по умолчанию папка `OlegPainter-github` рядом с проектом, или `OLEGPAINTER_PUBLIC_REPO`): делает его рабочую копию равной свежей выгрузке и показывает изменения. С описанием — `dev.ps1 publish "что изменилось"` — коммитит от автора этого репозитория (обязательно скрытая почта GitHub) и отправляет. Файлы в папке выгрузки руками не правьте: следующее обновление их заменит.

## Что означает успех

`check` подтверждает версии, импорты и ресурсы, отсутствие выбранных критических ошибок ruff и целостность локальных ссылок документации; правильность самого текста он не доказывает. Тесты проверяют поведение — пропуски и предупреждения читайте в выводе. Аварийное завершение процесса не считайте обычным падением assertion: изучите последнюю строку и воспроизведите проблемный модуль отдельно.
